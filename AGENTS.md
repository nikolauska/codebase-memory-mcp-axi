## Working on cbm-axi

This is a Node.js 24+ CLI for querying an independently installed `codebase-memory-mcp` backend (0.10.2+). It returns compact TOON through `axi-sdk-js`; it does not install or manage the backend. Use npm and the committed `package-lock.json`, not another package manager. Prefer Node standard-library APIs; add runtime dependencies only when needed and update the lockfile with the manifest.

- `src/cli.ts` registers commands through `runAxiCli`; command implementations live in `src/commands/`. Return structured values and use SDK errors rather than formatting CLI output by hand.
- `src/backend.ts` owns backend process invocation, version checks, and JSON-envelope decoding. Keep output projection and truncation separate from subprocess handling. Keep backend diagnostics out of successful structured output and disable upstream logging in the child environment.
- Use ESM TypeScript with `.js` relative import extensions. `dist/` is generated by `npm run build`; do not edit or commit it or `node_modules/`.
- For product behavior, consult `docs/domain/how-cbm-axi-works.md`; for contributing commands, consult `CONTRIBUTING.md`; for agent-facing usage, consult `skills/cbm-axi/SKILL.md`. Read these when relevant, not before every edit.

## Local verification

Run commands from the repository root. Tests inject backend runners and hook installers; they do not require the live backend or access live user configuration. Run relevant checks, fix failures caused by your change, and rerun affected checks without asking for routine approval.

- `npm ci` installs locked dependencies.
- `npm run build` compiles TypeScript to `dist/`; `npm test` builds first, then runs `test/cbm-axi.test.js` with Node's test runner.
- `npm run lint` checks lint, types, and test syntax; `npm run fmt:check` checks formatting; `npm pack --dry-run` builds and previews package contents.
- Before committing or opening a pull request, run `npm run fmt:check`, `npm run lint`, `npm test`, and `npm pack --dry-run` as described in `CONTRIBUTING.md`. For small edits before that point, use only the relevant checks.
- A live CLI check requires the separately installed backend on `PATH`. Do not treat its absence as a failure of the injected tests.

## Boundaries

- The backend and its configured graph storage are the source of truth. Test CLI behavior with injected runners; test session-hook changes with injected installers or temporary user directories, never live user configuration.
- `cbm-axi setup hooks` installs optional Claude Code, Codex, and OpenCode integrations through `axi-sdk-js`. Do not overwrite unmanaged OpenCode plugins or read, log, or commit secrets, credentials, private keys, or user configuration contents.
- Keep the version in `package.json` and `package-lock.json` aligned for releases. Tagged GitHub Actions runs publish and create release notes; do not run `npm publish` locally.
- Do not bypass hooks with `--no-verify` or force-push shared branches. If committing, use a conventional subject and a short description of what changed and why; no co-author trailer.
